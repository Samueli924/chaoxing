# Security and privacy

Do not post credentials, cookies, API keys, user data or raw captures in public issues or pull requests. If a credential was exposed, revoke or replace it; deleting the current file does not remove Git history.

The application authenticates to Chaoxing using supplied credentials. Saved local account files contain passwords and cookies. Optional answer providers receive questions and context; the writing provider may receive discussion reference text; notification services receive configured notifications. Review records and logs can contain personal course content, even after authentication redaction.

Use only accounts you are authorized to access. Keep the local data directory private. Logs redact authentication fields and configured secrets, and generated-text review records must be written before submission. No automated scan can certify that arbitrary user text contains no personal information.

If the repository offers private vulnerability reporting, use its Security page. Otherwise use a maintainer-provided private channel. Do not assume that a public issue or an unverified contact is private.
