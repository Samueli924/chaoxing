# 后续实测方案

目的：在自己有权使用的测试账号上，验证 [TEST_RESULTS.md](TEST_RESULTS.md) 4.5 节列出的"未在真实网站上验证"的部分，
并为向上游提交 PR 留下可复查的证据。所有判定都以学习通服务端自己的统计为准（章节页"已完成任务点: 完成数/总数"、
作答记录中的成绩），而不是以工具自己的日志为准。

## 0. 原则

1. **每个阶段前后各做一次只读核对**（第 3 节），用前后计数的差值判断本阶段做了什么、做对了没有。
2. **从小范围开始**：先单个章节，确认无误后再扩大。出现与预期不符的结果就停下，先保存日志再排查。
3. **证据脱敏后再提交**：只提交 `live_verify.py` 生成的报告；`live_trace.jsonl`、`chaoxing.log`、`cookies.txt` 含令牌，只留在本机。

## 2. 准备

```bash
git clone https://github.com/ieduer/chaoxing && cd chaoxing
pip install -r requirements.txt
export CHAOXING_DATA_DIR=./test-data          # 测试数据单独存放（Windows: set CHAOXING_DATA_DIR=test-data）
export CHAOXING_USERNAME=手机号 CHAOXING_PASSWORD=密码
python -m unittest discover -s tests          # 先确认 81 项单元测试通过
```

记下测试课程的课程ID（下文记作 `<测试课程ID>`），可从 `python main.py --check` 的输出或网页控制台的课程列表中看到。

## 3. 只读核对（每个阶段前后执行）

```bash
python scripts/live_verify.py -l <测试课程ID> -o docs/stage<N>_before.md     # 阶段开始前
python scripts/live_verify.py -l <测试课程ID> -o docs/stage<N>_after.md      # 阶段结束后
python scripts/live_verify.py -l <测试课程ID> --scores -o docs/stage<N>_after.md   # 需要成绩时
```

通过标准：报告第 1 节中"服务端待完成"与"工具解析待完成"相等（✅）。当前基线：测试课程 1/118，待完成 117。

## 4. 阶段 1：人脸识别参数视频（V1）

测试课程的第一个章节就是 1.1 导论，它的章节检测已经提交过，只剩这一个视频（总长 56.5 分钟，已看约 12.6 分钟）。

```bash
python main.py -l <测试课程ID> -j 1 -v
```

`-j 1` 让工具一次只处理一个章节，按章节顺序从 1.1 导论开始。看到日志出现
`任务完成: 开学第一课（无片头片尾小格式）.mp4`、下一个章节开始后，按 `Ctrl+C` 停止，再做一次只读核对。

| 结果 | 判定 |
| --- | --- |
| 服务端计数 1/118 → 2/118 | V1 通过：带人脸识别参数的视频可以正常计入 |
| 日志出现"视频已播放到结尾但服务器始终未判定完成" | V1 不通过：服务端要求人脸识别。保存 `chaoxing.log` 中该视频最后几次上报的返回内容，在文档中列为已知限制 |

## 5. 阶段 2：少量章节的章节检测（W1–W3）

按 [TUTORIAL.md](TUTORIAL.md) 第 6 节配置题库与提交方式后，继续用 `-j 1` 运行，完成 2～3 个章节后按 `Ctrl+C` 停止
（每个章节先播放视频，再处理章节检测；中位数视频约 13 分钟）。

| 检查点 | 在哪里看 | 通过标准 |
| --- | --- | --- |
| W1 解析 | 日志中每题的"填写答案为"行；`-v` 时 `chaoxing.log` 含原始页面 | 题目数量、题型与学习通页面一致，没有"未知题型"，题目中没有部首字符（如 ⻣、⻝） |
| W2 提交与成绩 | 日志"提交答题成功"及"成绩 X 分" | 只读核对中服务端计数每章增加 2（视频 + 章节检测）；`--scores` 报告中该测验有成绩，且与日志一致 |
| W3 重做 | 日志"章节检测重做第 N 轮"与"排除已答错的选项" | 重做后成绩不降低；同一道题不重复提交已判定错误的答案；若 `/work/retest` 失败，日志出现"章节检测无法重做（原因），保留当前成绩"且程序继续 |

W3 中"不允许重做"的情况取决于老师的设置，遇到时记录日志即可。

## 6. 阶段 3（可选）：完整运行与中断恢复（V2、E1）

```bash
python main.py -l <测试课程ID> -v              # 默认同时 4 个章节，按真实时长约 4～5 小时
```

运行约 30 分钟后按 `Ctrl+C` 中断一次，再用同一条命令重新运行（E1）：已完成的章节应显示"已完成所有任务点"并被跳过，
不重复播放、不重复提交。全部结束后做只读核对（带 `--scores`）。

通过标准：运行结果中"失败"为 0；服务端计数与预期一致；报告中没有未提交的章节检测。

## 7. 网页控制台端到端（U1）

```bash
python main.py --web
```

1. 登录 → 课程列表中两门课程与课程ID、班级ID正确。
2. 只勾选测试课程、选择章节检测方式后开始；确认进度条、正在播放的视频、日志实时刷新。
3. 第一个章节完成后点"停止"：状态变为已停止，结果汇总中完成数正确。
4. 不点"退出登录"、直接关闭并重新打开页面："使用上次的登录"可直接登录。
5. 点"退出登录"：已保存的登录状态会被删除，再次登录需要重新输入密码。

## 8. 题库对接（T1、T2）

- **T2（AI）**：在 `[tiku]` 中配置 `provider = AI` 及 `endpoint`、`key`、`model` 后启动，日志应出现"连接检查成功"
  （只发送一个"1+1 等于几"的测试请求，不涉及任何章节检测）。在阶段 2 中使用时，确认日志中答案来源为该题库。
- **T1（TikuCustom）**：在本机启动一个实现 `POST /api/search` 约定的题库服务（约定见 TUTORIAL 第 6 节），配置
  `provider = TikuCustom`、`custom_url`。在阶段 2 中确认服务端收到的请求体字段为 `question/type/options/key`，
  命中时日志显示"从自建题库服务器获取答案"，未命中时回退到下一个题库。
